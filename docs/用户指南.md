# S-AES 程序用户指南

本指南面向第一次运行程序的同学，按五个关卡说明每个界面怎么用、输入怎么写、
结果在哪里看。程序自身只依赖 Python 标准库。

---

## 1. 运行环境与启动

* Windows 10/11（也适用于安装了 Tk 的 Linux/macOS）；
* Python 3.10 及以上；
* 屏幕分辨率建议 1280×800 以上。

在项目根目录（`作业二/`）执行：

```bash
python -m gui.app
```

窗口顶部是标题栏，下方五个标签页依次对应作业的五个关卡。
所有标签页都可以用鼠标滚轮上下滚动。

---

## 2. 输入格式

密钥、明文、密文都支持两种写法：

| 写法 | 示例 | 说明 |
|---|---|---|
| 二进制 | `1010 0111 0011 1011` | 空格、下划线、冒号、逗号会被忽略；恰好 16 位且只含 0/1 时自动识别 |
| 二进制（带前缀） | `0b1010011100111011` | 明确按二进制解析 |
| 十六进制 | `A73B` | 不区分大小写 |
| 十六进制（带前缀） | `0xA73B` | 推荐写法，避免与二进制混淆 |

> 如果一个 16 位字符串只由 0 和 1 组成，程序会把它当作二进制。
> 想按十六进制解析 `0001101000101011` 这样的值，请写成 `0x0001101000101011`。

输入非法时程序会弹窗说明原因，不会修改你已经输入的内容。

## 3. 第 1 关 · 基本测试

![第 1 关界面](../results/screenshots/01a_basic.png)

1. 在「密钥 K（16 bit）」中输入密钥，例如 `1010 0111 0011 1011`；
2. 在「明文 / 密文（16 bit）」中输入 16 bit 数据；
3. 点「加密」，下方显示密文、十六进制/十进制值和往返校验结果；
4. 点「解密」时，同一个输入框作为密文使用，输出明文。

快捷按钮：

* **填入标准示例**：填入公开测试向量 `K = A73B`、`P = 6F6B`，
  期望密文 `C = 0738`；
* **随机示例**：随机生成密钥和数据并立即加密，适合快速演示；
* **清空**：清除输入、结果和中间过程。

加密/解密后，界面会按教材附录 D 的记号展开全过程：

* **附录 D 运算步骤与状态矩阵**：左侧列出
  `输入 → AK0 → NS → SR → MC → AK1 → NS → SR → AK2`
  （解密时为 `AK2 → ISR → INS → AK1 → IMC → ISR → INS → AK0`）；
  点击任意一行，右侧按图 D.2(a) 的列优先布局画出对应的 2×2 状态矩阵，
  单元格上标有 `s00 ~ s11` 和该半字节的十六进制值。
* **密钥扩展（D.3）**：逐行列出 `w0 ~ w5`、`g(w1)`、`g(w3)` 和
  `K0/K1/K2` 的二进制、十六进制及计算公式。
* **附录 D 结构对照**：给出加密/解密复合函数和四个基本变换的定义。

![运算步骤与状态矩阵](../results/screenshots/01b_basic_detail.png)

![密钥扩展明细](../results/screenshots/01c_basic_key.png)

![附录 D 结构对照](../results/screenshots/01d_basic_structure.png)

教材 D.3 的密钥扩展示例可以直接验证：输入 `K = 2D55`，密钥表会显示
`w2=BC、w3=E9、w4=A3、w5=4A`，即 `K1=BCE9、K2=A34A`。

## 4. 第 2 关 · 交叉测试

### 4.1 生成向量发给同学

![生成测试向量](../results/screenshots/02a_cross_generate.png)

1. 「生成数量」填 1~1000（默认 20）；
2. 「随机种子」可留空；填写同一个种子可复现同一批向量；
3. 「固定密钥」可留空（每组随机密钥），也可固定为同一个 16 bit 密钥；
4. 点「生成 CSV」，文本框中出现 `key,plaintext,ciphertext` 三列表格；
5. 点「复制」可直接粘贴到聊天窗口，点「保存为文件」可保存 `.csv`。

### 4.2 校验同学的向量

1. 把同学发来的向量粘贴到「校验同组同学的向量」文本框，
   每行三列，支持逗号、制表符或空格分隔，也可以保留表头；
2. 点「开始校验」；
3. 全部通过时显示绿色「全部 N 组向量通过，算法标准一致 ✓」；
   有失败时显示通过/失败数量，并在表格中列出期望密文与实际密文。

![交叉测试结果](../results/screenshots/02b_cross_check.png)

「算法标准」卡片把 S 盒、逆 S 盒、列混淆矩阵、RCON、状态布局和标准
向量全部列出，双方逐项核对即可快速定位差异。

![算法标准](../results/screenshots/02c_cross_standard.png)

> 常见差异原因：S 盒/逆 S 盒取值不同、状态矩阵按行而不是按列填充、
> 列混淆矩阵用成 AES 的 `[[2,3],[3,2]]`、密钥扩展中 `w2/w3` 或
> `w4/w5` 的顺序不同。

## 5. 第 3 关 · 扩展功能

![第 3 关](../results/screenshots/03a_text.png)

1. 输入 16 bit 密钥；
2. 在「明文」文本框输入任意字符串（UTF-8，纯 ASCII 与作业要求一致）；
3. 点「加密」：
   * 「密文（十六进制）」中每 2 字节一组显示；
   * 「可读形式」把可打印字符原样显示，不可打印字节显示为 `\xNN`；
   * 下方显示明文字节数、密文字节数和分组数；
4. 点「解密」会读取「密文（十六进制）」框中的内容并还原字符串。

「分组明细」表列出每组补齐后的明文字节和对应密文字节，
可以清楚看到 PKCS#7 填充（`01` 或 `02 02`）。

![第 3 关结果](../results/screenshots/03b_text_result.png)

> 解密失败通常是因为密钥不对或密文被改动。此时程序会提示填充不合法，
> 并在界面上显示未去填充的原始字节，便于判断问题。

## 6. 第 4 关 · 多重加密

### 6.1 双重加密（32 bit 密钥）

1. 在「密钥 K = K1 || K2」中输入 8 位十六进制（如 `1A2B3C4D`）；
2. 输入 16 bit 明文或密文；
3. 点「加密」或「解密」。结果下方会显示拆出的 K1、K2，
   加密时还显示中间值 `E_K1(P)`。

### 6.2 三重加密

1. 选择模式：
   * 两密钥 EDE（32 bit）：`E_K1(D_K2(E_K1(P)))`；
   * 三密钥 EDE（48 bit）：`E_K3(D_K2(E_K1(P)))`；
2. 按当前模式输入 8 位或 12 位十六进制密钥；
3. 输入 16 bit 数据后点「加密」/「解密」。

![多重加密](../results/screenshots/04a_multi_top.png)

### 6.3 中间相遇攻击

1. 点「生成演示数据」，程序随机选一个 32 bit 密钥，生成 3 组
   `(P, C)` 并填入文本框（真实密钥暂不显示）；
2. 点「开始攻击」，进度条显示正向建表和反向查表两个阶段；
3. 约 1~2 秒后显示候选密钥数量、K/K1/K2，以及演示数据真实密钥的核对结果。

![中间相遇攻击结果](../results/screenshots/04b_multi_mitm.png)

也可以自己准备向量：每行一组「明文 密文」，支持十六进制或二进制。
**建议至少 3 组**：一组向量平均会留下约 `2^16` 个候选密钥，
两组通常能缩到 1~4 个，三组基本保证唯一。

点「取消」可以在攻击中途停止。

## 7. 第 5 关 · CBC 模式

![CBC 模式](../results/screenshots/05a_cbc_top.png)

### 7.1 加密 / 解密

1. 输入 16 bit 密钥和 16 bit 初始向量 IV（双方必须共享同一个 IV）；
   点「随机 IV」可以生成一个 16 bit 随机向量（IV 不需要保密，但必须与解密端一致）；
2. 输入任意长度字符串，点「加密」；
3. 「密文」框显示十六进制密文，可直接编辑；
4. 点「解密」会读取密文框内容并还原明文。

「加密分组明细」列出每组明文、异或结果（`P_i ⊕ C_{i-1}`，第一组异或 IV）
和密文分组。

### 7.2 篡改演示

1. 先完成一次加密；
2. 设置「篡改分组」（从 1 开始）和「比特位置」（0 = 最低位，15 = 最高位）；
3. 点「翻转一位并解密」；
4. 左右两栏并排显示原始解密结果与篡改后解密结果，下方列出变化的字节
   和差错传播解释。

![CBC 篡改对比](../results/screenshots/05b_cbc_tamper.png)

典型现象：

* 被篡改的分组解密成随机噪声（整组两个字节都变）；
* 下一分组的**同一比特位**发生翻转（只变一个字节中的一位）；
* 更后面的分组完全不受影响。

注意：演示展示的是**未去填充**的原始字节。正常解密还会校验 PKCS#7 填充，
因此实际使用中密文被篡改往往直接报「填充不合法」。

## 8. 常见问题

**Q：为什么输入 `0001101000101011` 被当成二进制？**
A：恰好 16 位且只含 0/1 时按二进制解析。要按十六进制解析请加 `0x` 前缀。

**Q：交叉测试全部失败怎么办？**
A：先核对第 2 关「算法标准」卡片中的 S 盒、逆 S 盒、矩阵和状态布局；
再确认双方的二进制/十六进制解析方式一致。

**Q：CBC 解密提示填充不合法？**
A：密钥或 IV 不对，或者密文被修改过。IV 必须与加密端完全相同。

**Q：中间相遇攻击出现多个候选？**
A：向量组数太少。用界面的「生成演示数据」得到 3 组，或再增加一组
`(P, C)`，候选会收敛到唯一密钥。

**Q：窗口在高分屏上模糊？**
A：程序启动时已尝试开启 DPI 感知；若仍模糊，可在系统兼容性设置中
为 python.exe 关闭「替代高 DPI 缩放行为」。
